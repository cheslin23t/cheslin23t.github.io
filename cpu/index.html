The CPU

8-bit data. 16-bit instructions.

This is my programmable redstone CPU in Minecraft. It has a six-bit program counter, 64 instruction words, and two mirrored register banks feeding an eight-bit ALU.

The program below loads two values, adds them, and stores the result in R3. Scroll to follow it through the physical build. 

LDI R1, 165
LDI R2, 60
ADD R3, R2, R1

R3 = 225 165 + 60

Program memory

The program is stored in torches.

The ROM contains four layers of 16 words. Each word has 16 programming positions: a torch stores a 1; an empty position stores a 0.

The program counter selects a word. Its 16 bits feed the instruction bus, where some bits select the operation and others select registers or carry an immediate value.

4 layers × 16 words × 16 bits
1,024 physical bit positions

ROM · address 1

A58B is a physical pattern.

The first load is LDI R1, 165. Its word is A58B, or 1010010110001011. The close-up shows that word’s actual torch positions.

Physical bit 0 is the least significant bit—the rightmost digit above. Consecutive bits sit two blocks apart along the word.

Instruction decode

LDI sends a byte to R1.

A58B splits into an immediate byte, a destination field, and an opcode.

A5165
8R1
BLDI

The immediate byte is unchanged. Register numbers are bit-reversed within their four-bit fields: R1’s 0001 becomes 1000.

The LDI control selects the immediate data for writing. In this run, R1 reaches 10100101 at game tick 191.

Register banks

One byte, eight storage cells.

Each vertical slice holds eight bits. R1–R15 have a copy in each bank, so there are 240 storage repeaters. The copies provide matching register values to the operand paths.

R1 holds 165; R2 holds 60. The CPU reads these values later when the ADD instruction selects its operands.

R1 10100101 165
R2 00111100 60

ADD · control module

48C1 selects two sources and a destination.

The ADD sign marks the operation in the control module. Its instruction word routes R2 to operand A, R1 to operand B, and the result to R3.

4A: R2
8B: R1
CWrite R3
1ADD

The instruction contains register addresses, not the values 60 and 165. Those values come from the register banks. A different register selection uses the same ALU.

ALU · control inputs

Carry and inversion change the operation.

The mapped controls include carry-in, operand inversion, and OR. These change the signals entering the ALU rather than requiring a separate arithmetic unit for each instruction.

Carry-in adds one at the low end of the result. Inverting an eight-bit operand complements every bit: 00000001 becomes 11111110.

CIN with zero operands → 1
Invert A when A = 1 → 254

The CIN and !A locations are marked in this close-up. The operation decoder selects control signals from the instruction’s opcode.

ALU · propagation

The instruction changes before the result settles.

The ADD word reaches the instruction bus at tick 443. Signals then propagate through the operand paths and ALU.

At tick 463, the ALU output has not reached 225 yet. The readout shows the actual intermediate values from this run.

A = R2 = 60
B = R1 = 165

The native clock allows the data and write controls to propagate before moving to the next address.

ALU · result bus

Eight output wires carry 225.

At tick 497, the eight isolated output repeaters read 11100001. Bits 7, 6, 5, and 0 are on: 128 + 64 + 32 + 1. 

   00111100    60
 + 10100101   165
 ──────────
   11100001   225

The result is eight bits wide. Arithmetic wraps modulo 256; the destination receives the low eight result bits.

Output bit i · local (52, 22 + 2i, 18)

ALU · zero detection

The result also feeds a zero detector.

The dust staircase beside the output combines the result bits. Its torch produces the zero indication: it is on when all eight result bits are off.

Z = ¬(b₇ ∨ b₆ ∨ … ∨ b₀)

That combined line is a condition signal, not another eight-bit data bus. The independent output repeaters remain the source for the register value.

The build also has overflow and branch-control circuitry. Their complete behavior is not characterized, so they are not used in this program.

R3 · writeback

R3 retains the result.

R3 reaches 225 at tick 509. Its eight storage cells preserve that byte after the instruction changes.

By tick 650, the ALU is back at 0 and R3 is still 225. This close-up is R3’s low bit: electrically off, locked, and storing a logical 1.

ALU → 0
R3 → 225

A following instruction can select R3 as an operand and use the retained result.

Program counter

Six bits choose the next word.

The six state repeaters hold the ROM address. The native clock advances the counter once every 146 game ticks—7.3 seconds at normal Minecraft speed.

After the ADD, the PC advances from 3 to 4 at tick 569. The instruction bus takes additional time to reflect the new address.

The counter continues through the 64-word ROM and wraps. Stopping the clock pauses execution; there is no HALT instruction in this program.

Instruction set

What each operation changes.

Register operations select two operands and a destination. LDI supplies a byte directly; INC uses the B operand and adds one.

The examples use R1 = 165 and R2 = 60. Results are eight bits; NOT is limited to those eight bits.

Supported operations

Build files and implementation notes

The 3D model uses the physical schematic with simplified block shapes. The walkthrough uses the addition program; the replay switches the ROM to the line program. Orange shows powered dust and component tips; dark red shows off. Their states are captured from Minecraft each game tick; blue identifies components. Module crops are viewing regions, not complete netlists.

R1–R14 are available to the compiler; R0 reads as zero. R15 stores data but has faulty operand reads. DEC is faulty, ROM addresses 60/61 alias 56/57, and branch/overflow behavior remains unverified. Recording the internal signals does not certify every instruction or input combination.

The line plot reads the captured register coordinates; it is not a Minecraft display peripheral. The recordings began with registers cleared as test setup. PC reset does not clear registers. The test world was restored after capture.
